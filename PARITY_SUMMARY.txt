FINDING #1: Voice Command Parsing Logic Divergence
────────────────────────────────────────────────────
Severity: MEDIUM (Functional inconsistency)

Web:    lib/voice/commands.ts L38-44
        Regex-based: \b(triggers)\b\s*[,:-]?\s*
        Result: Flexible parsing ("Computer, do it" works)

Android: dictator-kotlin/dictator-core/.../VoiceCommandParser.kt L71-79
         Direct matching: normalized.contains(phrase.lowercase())
         Result: Strict parsing (must contain exact phrase)

Impact: Same voice input may be parsed differently across platforms
Status: Should align to regex approach for better UX consistency


FINDING #2: Sync Implementation Architecture Disparity
─────────────────────────────────────────────────────────
Severity: HIGH (Maintainability & feature risk)

Web:     lib/sync/ - 9 dedicated modules
         ├─ service.ts (305 LOC)
         ├─ conflict-resolution.ts (369 LOC)
         ├─ diff-service.ts (299 LOC)
         ├─ version-history.ts (306 LOC)
         ├─ version-branching.ts (327 LOC)
         ├─ sync-performance.ts (381 LOC)
         ├─ recovery-service.ts (239 LOC)
         ├─ sync-notification.ts (266 LOC)
         └─ index.ts (20 LOC)
         Total: 2512 LOC

Android: dictator-kotlin/dictator-core/.../SyncServiceImpl.kt
         Single consolidated class: 258 LOC
         (conflict resolution, versioning, recovery, all together)

Impact:  
  - Web: 9.7x more code, modular but complex interdependencies
  - Android: More maintainable but less explicit feature separation
  - Parity Risk: Edge case handling may diverge
  - Database Tech: Drizzle ORM (web) vs SQLite Multiplatform (android)

Status: Document expected behaviors; add Android integration tests


FINDING #3: Authentication Mechanism Divergence
────────────────────────────────────────────────
Severity: HIGH (Security & token management)

Web:     auth.ts - NextAuth.js
         ├─ Server-side HTTP sessions with httpOnly cookies
         ├─ Opaque session IDs
         ├─ Session stored on server
         └─ No token refresh needed (cookie-based)

Android: AuthServiceImpl.kt - Token-based
         ├─ JWT tokens
         ├─ Client-side storage (SharedPreferences)
         ├─ Authorization header on each request
         └─ Token expiration & refresh lifecycle

Impact:
  - No token sharing between platforms
  - Logout on web ≠ logout on Android
  - Different CSRF/token injection risk profiles
  - Multi-device session management not coordinated

Status: CRITICAL - Must document and align long-term
